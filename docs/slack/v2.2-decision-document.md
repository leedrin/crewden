# v2.2 — Decision & Document

> **给 Claude Code / Codex 的执行指令：** 实现本文档描述的 v2.2。按 TDD 工作：先写失败测试，再实现，再跑测试确认通过。完成后运行 `pnpm verify`。

## 背景

当前 Crewden 的频道讨论会产生大量结论，但这些结论会消失在聊天记录中。"我们决定了用方案 A"、"MVP 只支持单项目空间"——这些关键决策没有显式记录。

v2.2 引入两个新对象：

1. **Decision（ADR）**：显式记录架构决策、产品决策、技术选型等结论。有完整状态机（proposed → accepted → deprecated → superseded）。
2. **Document**：统一管理 PRD、TDD、Test Plan、Runbook、Postmortem 等工程文档。有独立状态机（draft → in_review → approved → deprecated → superseded）。

## 目标

- Decision 对象：完整 CRUD + 4 态状态机 + 关联 Thread/Task
- Document 对象：6 种文档类型 + 5 态状态机 + 关联 Thread/Decision/Task
- Thread 可显式创建 Decision 和 Document
- Task 执行时可检索关联的 Decision 和 Document

## 设计参考

> v2.2 的 Decision（ADR）和 Document 对象为 Crewden 原创设计，MultiCa 无对应概念。Document 的 5 态状态机（draft → in_review → approved → deprecated → superseded）参考了行业通用的文档生命周期模式。

## 非目标

- 不自动从 Thread 生成 Decision/Document（v2.3 Thread Intelligence 处理）
- 不做文档编辑器（使用 Markdown 文本字段）
- 不做文档审批流（v2.5 Approval Gate 处理）

## 数据模型

### Decision

```sql
CREATE TABLE IF NOT EXISTS decisions (
  id TEXT PRIMARY KEY,
  channel_id TEXT NOT NULL,
  source_thread_id TEXT,
  title TEXT NOT NULL,
  status TEXT NOT NULL DEFAULT 'proposed',  -- proposed | accepted | deprecated | superseded
  problem TEXT NOT NULL,
  alternatives TEXT,      -- JSON array
  decision_text TEXT NOT NULL,
  rationale TEXT,
  consequences TEXT,      -- JSON array
  participants TEXT,      -- JSON array of { actorType, actorId, role }
  related_decisions TEXT, -- JSON array of decision IDs
  superseded_by TEXT,
  created_at INTEGER NOT NULL,
  accepted_at INTEGER,
  updated_at INTEGER NOT NULL
);

CREATE INDEX idx_decisions_channel ON decisions(channel_id);
CREATE INDEX idx_decisions_status ON decisions(status);
```

### Document

```sql
CREATE TABLE IF NOT EXISTS documents (
  id TEXT PRIMARY KEY,
  kind TEXT NOT NULL,     -- prd | tdd | adr | rfc | test_plan | runbook | postmortem
  title TEXT NOT NULL,
  status TEXT NOT NULL DEFAULT 'draft',  -- draft | in_review | approved | deprecated | superseded
  content TEXT NOT NULL DEFAULT '',
  source_thread_id TEXT,
  source_channel_id TEXT NOT NULL,
  author_type TEXT NOT NULL,
  author_id TEXT NOT NULL,
  author_name TEXT NOT NULL,
  reviewers TEXT,         -- JSON array of { actorType, actorId }
  related_decisions TEXT, -- JSON array
  related_tasks TEXT,     -- JSON array
  superseded_by TEXT,
  created_at INTEGER NOT NULL,
  updated_at INTEGER NOT NULL,
  approved_at INTEGER
);

CREATE INDEX idx_documents_channel ON documents(source_channel_id);
CREATE INDEX idx_documents_kind ON documents(kind);
CREATE INDEX idx_documents_status ON documents(status);
```

## 实现任务

### Task 1：Shared protocol & validation

`packages/shared/src/protocol.ts`：增加 Decision, Document, DocumentKind, DecisionStatus, DocumentStatus 类型

`packages/shared/src/validation.ts`：增加 schema

### Task 2：Server Decision API

```http
GET    /api/channels/:id/decisions?status=accepted
POST   /api/decisions                     body: DecisionCreate
GET    /api/decisions/:id
PATCH  /api/decisions/:id                 body: DecisionUpdate
POST   /api/decisions/:id/deprecate
POST   /api/decisions/:id/supersede       body: { supersededBy: decisionId }
```

规则：

- 创建时状态只能是 `proposed`
- `accepted` 只能从 `proposed` 转换
- `deprecated` 和 `superseded` 只能从 `accepted` 转换
- superseded 时必须提供 supersededBy
- 所有操作写入 audit_log

**测试**：`packages/server/test/decisionsApi.test.ts`

### Task 3：Server Document API

```http
GET    /api/documents?kind=prd&status=approved
POST   /api/documents                     body: DocumentCreate
GET    /api/documents/:id
PATCH  /api/documents/:id                 body: DocumentUpdate
POST   /api/documents/:id/submit-review    body: { reviewers }
POST   /api/documents/:id/approve
POST   /api/documents/:id/deprecate
POST   /api/documents/:id/supersede        body: { supersededBy: docId }
```

规则：

- 创建时状态只能是 `draft`
- `submit-review` 将状态改为 `in_review`，必须提供 reviewers
- `approve` 将状态改为 `approved`，必须有 reviewers 中的 actor
- `deprecated` 和 `superseded` 只能从 `approved` 转换

**测试**：`packages/server/test/documentsApi.test.ts`
