# v2.4.1 — Code Hardening & Context Freshness

> **给 Claude Code / Codex 的执行指令：** 实现本文档描述的 v2.4.1。按 TDD 工作：先写失败测试，再实现，再跑测试确认通过。完成后运行 `pnpm verify`。

## 背景

v2.4 完成后进行了 [架构与功能评审](./Crewden%20v2.4%20架构与功能评审.md)，对照 Agentic Harness 六层模型和 v2.x 七层架构进行了全面审查。评审发现了两个必须在 v2.5 之前解决的 P0 问题，以及四个 P1/P2 改进项。

**P0 问题（本版本解决）：**

1. **代码结构债务**：`packages/server/src/db.ts`（2204 行）和 `packages/cloudflare/src/index.ts`（4470 行）是两个 God File。v2.0-v2.4 连续四个版本在末尾追加代码，未做任何模块化拆分。若 v2.5 继续叠加 Plan/Approval 功能，两个文件将分别突破 2500 行和 5000 行，开发速度和正确性保证将持续恶化。

2. **ContextPackage 无失效机制**：ContextPackage 生成后是静态快照。当关联的 documents/decisions 被更新、parent task 产生新交付物、或 thread 中出现新的关键决策时，ContextPackage 不会自动标记为 stale。Agent 可能在过期上下文上执行任务，产生错误的实现。

**不在本版本解决的 P1/P2 项（已补充到对应版本文档）：**

- P1-1：充实 hub-core 作为真正的业务逻辑层 → 见 [v2.5 Task 7](./v2.5-plan-approval.md)
- P1-2：Web 类型引入 shared → 见 [v2.5 Task 8](./v2.5-plan-approval.md)
- P2-1：MCP tool 描述预算控制 → 见 [v2.6 Task 5](./v2.6-code-execution-review.md)
- P2-2：Knowledge entry 上限控制 → 见 [v2.8 Task 6](./v2.8-knowledge-layer.md)

## 目标

本版本不增加任何新功能，专注代码健康：

1. **db.ts 拆分**：提取 Repository 层，将数据访问与业务逻辑分离
2. **cloudflare 拆分**：提取 DO 数据访问层，与 server Repository 共享接口
3. **hub-core 启用**：将 Task 状态机校验、Agent 委派匹配逻辑提取到 hub-core，消除 server/cloudflare 双端重复实现
4. **ContextPackage 失效机制**：document/decision 更新时自动标记关联 task 的 contextPackage 为 stale；agent 拉取 task 时检测 staleness 并触发自动重新生成

### Task 6：ContextPackage 失效机制 — 写入时标记 stale

**目标**：当 document 或 decision 被创建/更新/删除时，自动标记引用了它们的 task 的 contextPackage 为 stale。

实现路径：

1. `packages/server/src/routes/documents.ts` 和 `decisions.ts` 的 POST/PATCH/DELETE 端点中，增加钩子
2. 钩子查询 `context_package_refs` 表，找到引用了该 document/decision 的 task
3. 将对应 task 的 `context.contextPackage.stale` 设为 `true`，`staleReason` 记录触发原因

```typescript
// packages/server/src/repository/contextPackageRef.repository.ts（新增）
export interface ContextPackageRefRepository {
  addRef(taskId: string, refType: string, refId: string, refUpdatedAt: string): Promise<void>;
  removeRef(taskId: string, refType: string, refId: string): Promise<void>;
  findTasksByRef(refType: string, refId: string): Promise<string[]>;
}

export async function markContextPackagesStale(
  taskRepo: TaskRepository,
  cpRefRepo: ContextPackageRefRepository,
  refType: string,
  refId: string,
): Promise<number> {
  const taskIds = await cpRefRepo.findTasksByRef(refType, refId);
  for (const taskId of taskIds) {
    const task = await taskRepo.getById(taskId);
    if (task?.context?.contextPackage && !task.context.contextPackage.stale) {
      task.context.contextPackage.stale = true;
      task.context.contextPackage.staleReason = `${refType} updated: ${refId}`;
      await taskRepo.patch(taskId, { context: task.context }, task.version);
    }
  }
  return taskIds.length;
}
```

ContextPackage 生成时同步写入 refs：

```typescript
// generateAndStoreContextPackage 中增加
for (const section of cp.sections) {
  for (const ref of section.sourceRefs ?? []) {
    await cpRefRepo.addRef(task.id, ref.type, ref.id, ref.updatedAt);
  }
}
```

  const freshCp = await generateAndStoreContextPackage(task);

    task = (await getOrCreateDb().getTask(task.id))!;

}
