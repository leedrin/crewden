# v2.5 — Plan & Approval Gate

> **给 Claude Code / Codex 的执行指令：** 实现本文档描述的 v2.5。按 TDD 工作：先写失败测试，再实现，再跑测试确认通过。完成后运行 `pnpm verify`。

## 背景

Agent 不应该盲目执行——"先想再做的安全网。v2.5 引入两个机制：

1. **Plan**：Agent 执行编码任务前必须生成 Implementation Plan。高风险任务进入 Human-in-the-loop 审批。
2. **Approval Gate**：高风险操作必须有显式审批记录。提供统一审批流（pending → approved → rejected → expired）。

## 目标

- Plan 对象：draft → submitted → approved → rejected 状态机
- P0/P1 Task 的 Plan 必须 Reviewer 预审 + Human 审批
- P2/P3 Task 的 Plan 可 Reviewer-only 审批
- Approval 对象：统一审批流，超时自动拒绝
- 审批流集成到 Task 执行必经路径

## 数据模型

### Plan

```sql
CREATE TABLE IF NOT EXISTS task_plans (
  id TEXT PRIMARY KEY,
  task_id TEXT NOT NULL,
  status TEXT NOT NULL DEFAULT 'draft',  -- draft | submitted | approved | rejected
  approach TEXT NOT NULL,
  steps TEXT NOT NULL,          -- JSON array of { description, verification, estimatedTools }
  risks TEXT,                   -- JSON array of { description, mitigation }
  files_to_modify TEXT,         -- JSON array
  files_to_create TEXT,         -- JSON array
  tests_to_add TEXT,            -- JSON array
  author_type TEXT NOT NULL,
  author_id TEXT NOT NULL,
  reviewer_type TEXT,
  reviewer_id TEXT,
  reviewer_approved INTEGER,
  reviewer_comment TEXT,
  created_at INTEGER NOT NULL,
  updated_at INTEGER NOT NULL
);
```

### Approval

```sql
CREATE TABLE IF NOT EXISTS approvals (
  id TEXT PRIMARY KEY,
  type TEXT NOT NULL,           -- task_execution | architecture_decision | pr_merge | deploy_staging | deploy_production | ...
  target_id TEXT NOT NULL,      -- task_id / decision_id / pr_id
  status TEXT NOT NULL DEFAULT 'pending',  -- pending | approved | rejected | expired
  requested_by_type TEXT NOT NULL,
  requested_by_id TEXT NOT NULL,
  approved_by_type TEXT,
  approved_by_id TEXT,
  reason TEXT NOT NULL,
  context TEXT,
  requested_at INTEGER NOT NULL,
  responded_at INTEGER,
  expires_at INTEGER,           -- 超时自动 rejected
  comment TEXT
);

CREATE INDEX idx_approvals_target ON approvals(type, target_id);
CREATE INDEX idx_approvals_status ON approvals(status);
```

## 实现任务

### Task 1：Shared protocol & validation

增加 Plan, Approval, ApprovalType 类型和 schema

### Task 2：Plan API

```http
POST   /api/tasks/:id/plan                body: { approach, steps, risks, filesToModify, filesToCreate, testsToAdd }
GET    /api/tasks/:id/plan
POST   /api/tasks/:id/plan/submit
POST   /api/tasks/:id/plan/approve         (reviewer)
POST   /api/tasks/:id/plan/reject          (reviewer, with comment)
```

规则：

- `submit`：draft → submitted，提交给 reviewer
- `approve`：submitted → approved（reviewer 操作）
- `reject`：submitted → rejected（reviewer 操作，附 comment）
- P0/P1 Task 的 Plan approved 后还需 Human Approval 才能进入 in_progress
- P2/P3 Task 的 Plan approved 后可自动进入 in_progress

### Task 3：Approval API

```http
POST   /api/approvals                      body: { type, targetId, reason, context }
GET    /api/approvals?targetId=&type=&status=
POST   /api/approvals/:id/approve
POST   /api/approvals/:id/reject
GET    /api/approvals/pending               (当前用户待审批列表)
```

### Task 4：Task 状态推进集成

- `ready → assigned`：不需要 Approval
- `assigned → in_progress`：
  - P0/P1 Task：需要 Plan approved + task_execution Approval
  - P2/P3 Task：需要 Plan approved（不需要额外 Approval）
  - Docs/Research Task：不需要 Plan
- `in_review → qa`：不需要 Approval
- `qa → done`：需要 PR merged 检查

### Task 5：Web UI

- Task detail：Plan 预览/创建/审批区块
- Approval 列表页（当前用户的 pending approvals）
- Plan 审批表单（reviewer 视角：approve / reject + comment）

### Task 6：Agent-facing CLI

```bash
crewden task plan <taskId>                  # 查看当前 Plan
crewden task plan create <taskId> --approach "..." --steps-json '...'
crewden task approval list --status pending
crewden task approval respond <approvalId> --decision approve --comment "..."
```
