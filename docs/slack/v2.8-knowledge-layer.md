# v2.8 — Knowledge Layer

> **给 Claude Code / Codex 的执行指令：** 实现本文档描述的 v2.8。按 TDD 工作：先写失败测试，再实现，再跑测试确认通过。完成后运行 `pnpm verify`。

## 背景

v1.5 已经实现 Knowledge & Memory Layer，包含可检索的 knowledge entry、API、Agent-facing tools 和 Web Knowledge panel。v2.8 不是从零新建知识库，而是在现有 v1.5 knowledge layer 上升级：补充分层 scope、使用统计、Task 自动沉淀和 Context Package 检索增强，让 Agent 执行前能拿到更贴合任务的项目经验。

## 目标

- 升级现有 Knowledge Entry：增加分层存储（agent scope / workspace scope / global scope）
- 沿用 v1.5 kind：decision / project_archive / user_preference / runbook / learning / artifact
- Task done → 自动提取经验 → learning kind 草稿
- Project/Goal 完成 → 自动生成 project_archive
- 知识卫生：stale / conflict / archived 标记
- Agent 执行前检索相关知识

### Task 6：Knowledge Entry 上限控制（P2-2 from v2.4.1 评审）

> 来源：[v2.4.1 架构评审 P2-2](./v2.4.1-code-hardening.md) — Knowledge entries 无上限控制，长期运行可能无限增长，占用存储和检索性能。

实现路径：

1. **设置上限**：默认每个 scope 最多 1000 条 knowledge entry（可配置 `CREWDEN_KNOWLEDGE_MAX_ENTRIES`）
2. **达到阈值时触发「审查与晋升」**：
   - 新 entry 写入时若已达上限，返回 429 并提示清理
   - 自动扫描 stale/conflict 条目，生成清理建议
   - 高价值条目可晋升为 `runbook` 或 `project_archive`（更稳定的 kind）
3. **自动淘汰策略**（可选开启）：
   - 优先淘汰 `stale=true` + `last_used_at` 最旧的条目
   - `kind=learning` 优先于 `kind=runbook` 被淘汰
   - `scope=agent` 优先于 `scope=project` 优先于 `scope=global`

```typescript
// hub-core/src/knowledgeRetention.ts（新增）
export async function enforceKnowledgeLimit(
  repo: KnowledgeRepository,
  scope: KnowledgeScope,
  maxEntries: number = 1000,
): Promise<{ removed: number; suggestions: string[] }> {
  const count = await repo.countByScope(scope);
  if (count < maxEntries) return { removed: 0, suggestions: [] };
  // 扫描 stale/conflict 条目
  // 生成清理建议
  // 若开启自动淘汰，删除最不重要的条目
}
```
