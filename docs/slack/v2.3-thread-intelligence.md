# v2.3 — Thread Intelligence

> **给 Claude Code / Codex 的执行指令：** 实现本文档描述的 v2.3。按 TDD 工作：先写失败测试，再实现，再跑测试确认通过。完成后运行 `pnpm verify`。

## 背景

当前 Thread 只是消息的容器，没有结构化能力。Agent 需要阅读整个 Thread 才能理解上下文，导致 token 浪费和注意力分散。

v2.3 给 Thread 加上三个核心能力：
1. **自动摘要**：Thread 消息数 > 阈值时自动生成摘要
2. **意图分类**：识别用户消息是闲聊、任务请求还是目标型请求
3. **Agent Inbox v2**：统一的 Agent 收件箱（任务/提及/Review/阻塞）

## 目标

- Thread 自动摘要：> 10 条消息触发，resolved 时生成最终摘要
- 消息意图分类：chat / task / goal（规则 + 可选 LLM）
- Agent Inbox 统一化：assigned tasks + @mentions + pending reviews + blocked items
- Thread 摘要作为 Context Package 输入（v2.4 使用）

## 实现任务

### Task 1：Thread 扩展 + 自动摘要 API

`packages/server/src/routes/threads.ts`：

```http
GET    /api/threads/:id
POST   /api/threads/:id/resolve
POST   /api/threads/:id/reopen
GET    /api/threads/:id/summary
```

摘要生成规则（v2.3 使用规则，LLM 可选）：

```
提取最后 10 条消息 → 按 actor 分组 → 提取关键短语
  → 格式：
    "# {title}"
    "Participants: {actor1}({role1}), {actor2}({role2})"
    "Key points:"
    "- {point1}"
    "- {point2}"
    "Decisions:"
    "- {decision1}"
    "Open questions:"
    "- {question1}"
```

**测试**：`packages/server/test/threadsApi.test.ts`

- Thread 消息数 > 10 触发自动摘要
- Thread resolved 生成最终摘要
- 摘要可读且包含关键信息

### Task 2：消息意图分类

新增 `packages/hub-core/src/intentClassifier.ts`：

```typescript
function classifyMessageIntent(message: Message): MessageIntent {
  // 规则：
  // 包含 帮我做/实现/调研/规划/推进/完成 等动作词
  //   + 需要多步协作 → goal
  // 包含以上动作词
  //   + 单步事项 → task
  // 否则 → chat
}
```

消息创建时自动计算 intent，存储到 Message 字段。

**测试**：`packages/hub-core/test/intentClassifier.test.ts`

- "帮我做一个外卖 App 的 MVP 方案" → goal
- "Review 一下这个 PR" → task
- "今天天气不错" → chat

### Task 3：Agent Inbox v2 API

`packages/server/src/routes/inbox.ts`：

```http
GET /internal/agent/:agentId/inbox
```

返回聚合的 inbox items：

1. 分配给该 Agent 的 open tasks（按 priority 排序）
2. 最近 @ 该 Agent 的 messages（未读）
3. 待处理的 review requests
4. 被阻塞的 tasks
5. 订阅的 threads 有新消息

**测试**：`packages/server/test/inboxApi.test.ts`

### Task 7：Paseo Send Behavior 对齐

- Channel/Thread 发消息接口支持 `deliveryBehavior`：`interrupt | queue`
- `interrupt`：立即发送并允许替换当前运行中的 turn
- `queue`：当 Agent 正在运行时进入队列，等待 turn 结束后按顺序发送
- 保持 Cloudflare parity，避免依赖常驻进程；队列消费基于 runtime 事件驱动
