# v2.7 — Autopilot Engine

> **给 Claude Code / Codex 的执行指令：** 实现本文档描述的 v2.7。按 TDD 工作：先写失败测试，再实现，再跑测试确认通过。完成后运行 `pnpm verify`。

## 背景

Agent 当前的触发方式是被动的——人等 Agent 或 Agent 检查 inbox。v2.7 引入 Autopilot，让系统能按规则自动触发 Agent 工作。

## 目标

- Autopilot 引擎：Schedule / Webhook / Event 三种触发方式
- 两种执行模式：create_task（创建 Task 到看板）/ send_message（发消息到 Channel）
- 并发策略：skip / queue / replace
- 4 个内置模板：Bug Triage / PR Review Reminder / Weekly Report / Security Scan

### Crewden 差异点

- Event 触发方式（MultiCa 无）→ Crewden 新增
- role-based assignee 解析（MultiCa 直接 agent_id）→ Crewden 新增

## 数据模型

```sql
CREATE TABLE IF NOT EXISTS autopilots (
  id TEXT PRIMARY KEY,
  title TEXT NOT NULL,
  assignee_type TEXT NOT NULL,     -- agent | role
  assignee_id TEXT NOT NULL,
  execution_mode TEXT NOT NULL,    -- create_task | send_message
  task_template TEXT,              -- JSON: title template, body, priority, channelId
  concurrency_policy TEXT NOT NULL DEFAULT 'skip',
  enabled INTEGER NOT NULL DEFAULT 1,
  created_at INTEGER NOT NULL,
  updated_at INTEGER NOT NULL
);

CREATE TABLE IF NOT EXISTS autopilot_triggers (
  id TEXT PRIMARY KEY,
  autopilot_id TEXT NOT NULL,
  kind TEXT NOT NULL,              -- schedule | webhook | event
  cron_expression TEXT,
  timezone TEXT DEFAULT 'UTC',
  last_run_at INTEGER,
  next_run_at INTEGER,
  webhook_url TEXT,
  webhook_secret TEXT,
  event_type TEXT,
  event_filter TEXT,               -- JSON
  created_at INTEGER NOT NULL
);

CREATE TABLE IF NOT EXISTS autopilot_runs (
  id TEXT PRIMARY KEY,
  autopilot_id TEXT NOT NULL,
  trigger_id TEXT,
  status TEXT NOT NULL,
  -- queued | running | task_created | completed | failed | skipped | cancelled
  source TEXT,
  triggered_at INTEGER NOT NULL,
  completed_at INTEGER,
  result_task_id TEXT,
  error TEXT
);
```

`autopilot_runs.status` 语义：

| 状态 | 含义 |
|------|------|
| `queued` | queue 策略下等待前一个 active run 结束，尚未执行 |
| `running` | 已被调度并开始解析 assignee / 执行模式 |
| `task_created` | create_task 模式已创建关联 Task，等待 Task 终态回写 |
| `completed` | send_message 已发送，或关联 Task 已 `done` |
| `failed` | 调度失败，或关联 Task 被 `cancelled` / 执行失败 |
| `skipped` | skip 策略下因已有 active run 被跳过 |
| `cancelled` | replace 策略取消旧 active run |

`hasActiveRun(autopilotId)` 只统计 `running` / `task_created`；`queued` 不算 active，避免 resume 时被自己的队列项拦截。

### Task 2：Schedule 调度器

**调度策略（Cloudflare-safe）：**

Crewden 同时部署在 Node Server 和 Cloudflare Workers。调度器必须同时支持两种环境：

| 环境 | 调度方案 | 说明 |
|------|---------|------|
| **Node Server** | `setInterval` 每 30s 扫描 + 补偿检查 | Server 启动时额外做一次 retroactive scan，覆盖停机期间的到期 trigger |
| **Cloudflare Workers** | **Durable Object Alarm** | `state.storage.setAlarm(Date.now() + 30_000)`，alarm 触发后扫描 + 递归设置下一次 alarm。**不依赖常驻 setInterval** |

> **约束**：不可依赖进程级常驻定时器作为唯一调度手段。Cloudflare Workers 的请求处理是短生命周期的，`setInterval` 在 Worker 环境中不可靠且违反最佳实践。

**扫描逻辑（两种环境共用）：**

```sql
SELECT t.*, a.*
FROM autopilot_triggers t
JOIN autopilots a ON a.id = t.autopilot_id
WHERE t.kind = 'schedule'
  AND t.next_run_at <= ?
  AND a.enabled = 1
```

每次扫描后更新 `autopilot_triggers.next_run_at = computeNextRun(cron_expression, timezone)`。

### Task 5：Dispatch 逻辑

```typescript
async function dispatchAutopilot(autopilot, trigger, source, opts?: { resumeRunId?: string }): Promise<void> {
  let run: AutopilotRun;

  // 1. 并发策略检查
  if (opts?.resumeRunId) {
    run = await claimQueuedRun(opts.resumeRunId); // queued -> running，跳过并发检查
  } else {
    const hasActive = await hasActiveRun(autopilot.id);
    if (autopilot.concurrencyPolicy === 'skip' && hasActive) {
      await recordRun('skipped', 'previous run still active');
      return;
    }
    if (autopilot.concurrencyPolicy === 'replace' && hasActive) {
      await cancelActiveRun(autopilot.id);
    }
    if (autopilot.concurrencyPolicy === 'queue' && hasActive) {
      await createRun({ autopilot, trigger, source, status: 'queued' });
      return; // 等前一个 run 完成后由 dispatchNextQueuedRun resume
    }
    run = await createRun({ autopilot, trigger, source, status: 'running' });
  }

  // 2. 解析 assignee
  let agentId: string;
  if (autopilot.assigneeType === 'agent') {
    agentId = autopilot.assigneeId;
  } else {
    const candidates = resolveAgents({ role: autopilot.assigneeId, mustBeIdle: false });
    agentId = candidates[0]?.agent.id;
  }
  if (!agentId) {
    await updateRunStatus(run.id, 'failed', { error: 'no suitable agent' });
    await dispatchNextQueuedRun(run.autopilotId);
    return;
  }

  // 3. 执行模式
  // create_task 模式不是创建 task 后就完成；最终完成/失败由 SyncRunFromTask 驱动。
  if (autopilot.executionMode === 'create_task') {
    const task = await createTaskFromTemplate(autopilot.taskTemplate, agentId);
    await updateRunStatus(run.id, 'task_created', { resultTaskId: task.id });
  } else if (autopilot.executionMode === 'send_message') {
    await sendMessage(autopilot.taskTemplate.channelId, agentId, autopilot.taskTemplate.title);
    await updateRunStatus(run.id, 'completed'); // send_message 无关联 task，直接完成
    await dispatchNextQueuedRun(run.autopilotId);
  }
}
```

### Task 5b：Run 生命周期联动

```typescript
// 核心原则：create_task 模式的 run 不是"已创建任务"就完成，
// 而是跟踪关联 task 的最终状态（done/failed/cancelled）后才结束。

// 在 Task 状态变更的事件监听中调用：
async function syncRunFromTask(taskId: string, newStatus: TaskStatusV2): Promise<void> {
  const run = await getRunByTaskId(taskId);
  if (!run || run.status === 'completed' || run.status === 'failed') return;

  switch (newStatus) {
    case 'done':
      await updateRunStatus(run.id, 'completed');
      // queue 策略：触发下一个排队的 run
      await dispatchNextQueuedRun(run.autopilotId);
      break;
    case 'cancelled':
      await updateRunStatus(run.id, 'failed', { reason: 'task cancelled' });
      await dispatchNextQueuedRun(run.autopilotId);
      break;
    // in_progress / in_review / qa 等中间状态不改变 run 状态
  }
}

// queue 策略：前一个 run 结束后消费下一个排队的 run
async function dispatchNextQueuedRun(autopilotId: string): Promise<void> {
  const next = await getNextQueuedRun(autopilotId);
  if (!next) return;
  const autopilot = await getAutopilot(autopilotId);
  const trigger = await getTrigger(next.triggerId);
  await dispatchAutopilot(autopilot, trigger, 'queue_resume', { resumeRunId: next.id });
}
```
