# v2.2.1 — Project 多项目隔离

> **给 Claude Code / Codex 的执行指令：** 实现本文档描述的 v2.2.1。按 TDD 工作：先写失败测试，再实现，再跑测试确认通过。完成后运行 `pnpm verify`。

## 背景

v2.0 统一了 Polymorphic Actor，v2.1 建立了 Agent 身份体系，v2.2 引入了 Decision 和 Document。但这三个版本的所有对象（Channel、Task、Agent、Decision、Document）都平铺在单一空间内，无法支持多项目并行开发。

**痛点**：

- 团队有多个并行项目（后端服务 + 前端 App + 内部工具），所有 Channel 混在一起
- Task Board 无法按项目过滤，Backlog 列堆满不同项目的任务
- Agent 权限没有项目边界——安全 Agent 能看到所有项目的敏感信息
- Paseo 原生支持多 project 管理，Crewden 却没有利用这一能力
- v2.7 Autopilot 没有作用域——"每日 Bug Triage" 会对所有项目的 issues 生效
- v2.8 Knowledge 的 scope 分层缺少顶层容器

v2.2.1 在已完成的 v2.0-v2.2 地基上，引入 **Project** 作为隔离边界。

## 设计参考

> 参考 [MultiCa 任务系统可行性调研](./multica-task-board-feasibility.md) 中 MultiCa 的 workspace 隔离设计（28 张表全部带 `workspace_id`），以及 Paseo 原生多 project 管理能力。

| 参考来源 | 提取内容 |
|---------|---------|
| **MultiCa** | 所有核心表带 `workspace_id` + 外键级联 + 索引；member 通过 n-n 关联 workspace；全局路由 `/{slug}/...` 模式 |
| **Paseo** | 原生 project 概念：每个 project 有独立 agent 组、session、工作目录。Crewden Project 与 Paseo project 1:1 映射 |
| **Linear / Notion** | 侧边栏 workspace/project 切换 UX 模式 |

## 目标

- 引入 Project 对象：id、name、slug、description、paseoProjectId
- 所有现有对象（Channel、Task、Agent、Decision、Document、audit_log）增加 `project_id`
- Project 内隔离：Channel 列表、Task Board、Decision/Document 列表默认只显示当前 project 的数据
- Project 切换：侧边栏 project switcher
- 现有数据自动迁移到默认 project，不丢失

## 非目标

- 不做跨 project 的 Channel/Thread（v2.x 阶段内 project 之间完全隔离）
- 不做 project 级别的成员/权限（沿用现有 Agent 权限模型，project 由 owner 管理）
- 不做 project 模板
- 不改变现有的 Agent 文件 workspace 概念（那是 agent 的工作目录，与 project 是不同的概念）
- **不做 Paseo project 自动创建**——Crewden Project 创建时需手动关联已有 Paseo project，或留空

---

## 概念澄清

Crewden 中存在三个容易混淆的"空间"概念，v2.2.1 后明确区分：

| 概念 | 含义 | 示例 | 边界 |
|------|------|------|------|
| **Project** | 业务项目隔离容器 | "电商后端" / "移动App" / "内部工具" | Channel、Task、Agent、Decision、Document 全部归属 project |
| **Agent Workspace** | Agent 的文件工作目录 | `~/crewden_workspaces/{agentId}/workdir/` | 文件级别，每个 agent 独立 |
| **Paseo Project** | Paseo 运行时内的 agent 组 | Paseo Daemon 中的 project 概念 | Agent 进程管理、session 持久化 |

**关系**：Crewden Project 1:1 Paseo Project（可选关联）。Agent 归属于某个 Crewden Project，并在对应 Paseo Project 中运行。

## 数据模型

### Project 表

```sql
CREATE TABLE IF NOT EXISTS projects (
  id TEXT PRIMARY KEY,
  name TEXT NOT NULL,
  slug TEXT UNIQUE NOT NULL,
  description TEXT DEFAULT '',
  paseo_project_id TEXT,            -- 可选：关联的 Paseo project id
  created_at TEXT NOT NULL,         -- ISO timestamp
  updated_at TEXT NOT NULL          -- ISO timestamp
);
```

### 现有表增加 project_id

```sql
-- Channel
ALTER TABLE channels ADD COLUMN project_id TEXT NOT NULL DEFAULT 'default';
CREATE INDEX idx_channels_project ON channels(project_id);

-- Task（v2.0 已升级）
ALTER TABLE tasks ADD COLUMN project_id TEXT NOT NULL DEFAULT 'default';
CREATE INDEX idx_tasks_project ON tasks(project_id);

-- Agent（v2.1 已升级）
ALTER TABLE agents ADD COLUMN project_id TEXT NOT NULL DEFAULT 'default';
CREATE INDEX idx_agents_project ON agents(project_id);

-- Decision（v2.2）
ALTER TABLE decisions ADD COLUMN project_id TEXT NOT NULL DEFAULT 'default';
CREATE INDEX idx_decisions_project ON decisions(project_id);

-- Document（v2.2）
ALTER TABLE documents ADD COLUMN project_id TEXT NOT NULL DEFAULT 'default';
CREATE INDEX idx_documents_project ON documents(project_id);

-- audit_log（v2.0）
ALTER TABLE audit_log ADD COLUMN project_id TEXT NOT NULL DEFAULT 'default';
CREATE INDEX idx_audit_project ON audit_log(project_id);

-- messages（v2.0 已升级 actor 字段）
ALTER TABLE messages ADD COLUMN project_id TEXT NOT NULL DEFAULT 'default';
CREATE INDEX idx_messages_project ON messages(project_id);

-- 注意：当前 Crewden 无独立 threads 表，thread 由 messages.thread_root_id 推导
-- 因此 thread 级 project 隔离通过 messages.project_id + 查询约束实现

-- goals (v1.1)
ALTER TABLE goals ADD COLUMN project_id TEXT NOT NULL DEFAULT 'default';
CREATE INDEX idx_goals_project ON goals(project_id);

-- goal_alignments (v1.2)
ALTER TABLE goal_alignments ADD COLUMN project_id TEXT NOT NULL DEFAULT 'default';

-- knowledge_entries (v1.5 / v2.8)
ALTER TABLE knowledge_entries ADD COLUMN project_id TEXT NOT NULL DEFAULT 'default';
CREATE INDEX idx_knowledge_project ON knowledge_entries(project_id);

-- reminders (v0.7)
ALTER TABLE reminders ADD COLUMN project_id TEXT NOT NULL DEFAULT 'default';
```

### 迁移策略

```sql
-- 1. 创建默认 project
INSERT INTO projects (id, name, slug, description, created_at, updated_at)
VALUES ('default', 'Default Project', 'default', 'Auto-created during v2.2.1 migration',
        datetime('now'), datetime('now'));

-- 2. 所有现有数据的 project_id 已通过 DEFAULT 'default' 填充
-- 3. 后续用户可创建更多 project 并迁移数据
```

## API 设计

### Project CRUD

```http
GET    /api/projects                              # 列出所有 project
POST   /api/projects                              # 创建 project
GET    /api/projects/:id                           # 获取 project 详情
PATCH  /api/projects/:id                           # 更新 project
DELETE /api/projects/:id                           # 删除 project（级联）
```

> 修正：默认 **不允许级联删除**。若 project 下仍有 Channel/Task/Agent/Decision/Document，
> 删除请求应返回冲突错误，需先迁移或清理数据后再删除。

### 现有 API 增加 project 过滤

所有列表类 API 新增可选 query param `projectId`：

```http
GET /api/channels?projectId=xxx
GET /api/tasks?projectId=xxx&status=in_progress
GET /api/decisions?projectId=xxx&status=accepted
GET /api/documents?projectId=xxx&kind=prd
GET /api/agents?projectId=xxx
GET /api/audit?projectId=xxx
GET /api/knowledge?projectId=xxx
GET /api/reminders?projectId=xxx
```

- `projectId` 为空时返回所有 project 的数据（向后兼容）
- 创建对象时 `project_id` 必填

### WebSocket 事件增加 project_id

所有现有的 WebSocket 事件 payload 增加 `project_id` 字段，前端按当前 project 过滤展示。

interface Project {
  id: string;

## 对后续版本的影响

v2.2.1 引入 Project 后，后续版本在设计时需注意：

| 后续版本 | 影响 |
|---------|------|
| v2.3 Thread Intelligence | Agent Inbox 需按 project 过滤；Thread 摘要生成需感知 project context |
| v2.4 Context Package | Context Package 检索范围限定当前 project |
| v2.5 Plan & Approval | Plan 和 Approval 归属 project；审批通知按 project 路由 |
| v2.6 Code Execution | Git 仓库白名单按 project 配置 |
| v2.7 Autopilot | Autopilot 绑定 project；调度范围限定当前 project 的 agent 和 task |
| v2.8 Knowledge Layer | scope 分层调整为 `agent / project / global`（原 `workspace` → `project`） |
| v2.9 Full Trace | Trace 按 project 过滤 |
| v2.10 Self-Evolution | Skill 沉淀按 project 隔离 |

详见各版本文档的「project 影响」节。
