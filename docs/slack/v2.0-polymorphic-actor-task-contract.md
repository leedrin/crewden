# v2.0 — Polymorphic Actor + Task Execution Contract

> **给 Claude Code / Codex 的执行指令：** 实现本文档描述的 v2.0。按 TDD 工作：先写失败测试，再实现，再跑测试确认通过。完成后运行 `pnpm verify`。

## 背景

当前 Crewden（v1.5.1）已完成 Paseo Runtime 单栈收敛，协作层有 Channel / DM / Task Board / Agent Profile。但存在以下缺口：

1. **Actor 模型不统一**：Message 的 author 只有 human userId，Agent 的消息通过特殊路径注入。Task / Comment / Delegation 的 creator 字段各自独立。
2. **Task 状态机过简**：task 只有 `open / in_progress / review / done`，缺少关键中间状态（spec 不完整、被阻塞、QA 验证）。
3. **缺少 triage 机制**：原始想法直接进 todo，缺少"需求还不清晰，需要先补充"的中间列。
4. **缺少审计基础**：关键动作没有统一的 audit log。

v2.0 是 v2.x 系列的地基——**在开始任何上层功能之前，先把数据模型统一、状态机敲实**。

## 目标

- 所有协作对象使用统一的 Polymorphic Actor 模型（`actorType + actorId`）。
- Task 状态机从 4 态升级到 10 态。
- 引入 triage 机制（`spec_needed` 状态），原始想法先入 Backlog 列并标「Needs Spec」，补充完整规格后进入 Todo 列。
- 引入基础 audit log，记录 Task 创建/状态变更/delegation 等关键路径。
- 现有数据迁移，不破坏已有用户数据。

## 非目标

- 不做 Context Package、Plan、Approval —— 这些是 v2.3-v2.5 的内容。
- 不做 Agent 角色权限系统 —— v2.1 处理。
- 不做 Thread 摘要 —— v2.3 处理。
- 不改 Paseo 协议层。

## 数据模型

### Polymorphic Actor 统一

所有涉及"谁"的字段改为：

```ts
interface Actor {
  actorType: 'human' | 'agent' | 'system';
  actorId: string;
}
```

应用于：

| 对象 | 字段 | 改造说明 |
|------|------|---------|
| Message | author | `senderId` → `actorType + actorId`，保留 `senderName` 做展示 |
| Task | creator, owner, reviewer | 新增 `actorType + actorId` 对 |
| Comment | author | 新增 `actorType + actorId` |
| Delegation | from, to | `fromAgentId` → `actorType + actorId` |

### Task 状态机升级

```ts
// 10 个正式状态。blocked 不独立成态，通过 task.isBlocked + task.blockedReason 子标记表达。
// released 状态留到 v2.6+ 部署管道阶段再引入。
type TaskStatusV2 =
  | 'backlog'              // 1：待办池
  | 'spec_needed'          // 2：等待补充规格（Backlog 列中的 Needs Spec 细节态）
  | 'ready'                // 3：已就绪
  | 'assigned'             // 4：已分配
  | 'in_progress'          // 5：执行中
  | 'in_review'            // 6：审查中
  | 'changes_requested'    // 7：需修改（rework）
  | 'qa'                   // 8：QA 验证
  | 'done'                 // 9：完成
  | 'cancelled';           // 10：取消

// 合法状态转换（仅含 10 个正式态，无 blocked 跃迁）
const VALID_TASK_TRANSITIONS: Record<TaskStatusV2, TaskStatusV2[]> = {
  'backlog':           ['spec_needed', 'ready', 'cancelled'],
  'spec_needed':       ['ready', 'backlog'],
  'ready':             ['assigned', 'backlog', 'cancelled'],
  'assigned':          ['in_progress', 'ready', 'cancelled'],
  'in_progress':       ['in_review', 'cancelled'],
  'in_review':         ['changes_requested', 'qa', 'done', 'cancelled'],
  'changes_requested': ['in_progress', 'cancelled'],
  'qa':                ['done', 'changes_requested', 'cancelled'],
  'done':              [],
  'cancelled':         [],
};

// blocked 语义：task.status 保持 in_progress，额外设置 task.isBlocked=true
//   并填充 task.blockedReason。Board 渲染时 isBlocked 的卡留在 "In Progress" 列，
//   以红色左边框 + 🚫 标记区分，不单独设列。unblock 只需 isBlocked=false。
```

### 看板列映射（5 列 UI ← 10 态数据）

10 态状态机提供完整的 API/审计/自动化语义，前端看板收敛为 5 列以保持可浏览性：

| 看板列 | 包含的数据态 | 列内视觉区分 |
|--------|------------|-------------|
| **Backlog** | `backlog` + `spec_needed` | `spec_needed` 显示 🏷️ "Needs Spec" 标签 |
| **Todo** | `ready` | — |
| **In Progress** | `assigned` + `in_progress` | `assigned` 浅色卡；`isBlocked=true` 红色左边框 + 🚫 |
| **Review** | `in_review` + `changes_requested` + `qa` | `changes_requested` 🏷️ "Rework"；`qa` 🏷️ "QA" |
| **Done** | `done` + `cancelled` | `cancelled` 灰色 + 删除线 |

拖拽跨列时映射到对应状态转换（如 Review→In Progress：`changes_requested` → `in_progress`）。每列内支持按细节态筛选，移动端默认列表视图。

### Audit Log 表

```sql
CREATE TABLE IF NOT EXISTS audit_log (
  id TEXT PRIMARY KEY,
  actor_type TEXT NOT NULL,  -- human | agent | system
  actor_id TEXT NOT NULL,
  action TEXT NOT NULL,       -- task_created | task_status_changed | task_assigned | ...
  entity_type TEXT NOT NULL,  -- task | message | delegation
  entity_id TEXT NOT NULL,
  detail TEXT,                -- JSON
  created_at INTEGER NOT NULL
);

CREATE INDEX idx_audit_entity ON audit_log(entity_type, entity_id);
CREATE INDEX idx_audit_actor ON audit_log(actor_type, actor_id, created_at);
```

### Message 表结构扩展

```sql
ALTER TABLE messages ADD COLUMN actor_type TEXT NOT NULL DEFAULT 'human';
ALTER TABLE messages ADD COLUMN actor_id TEXT;

-- 迁移现有数据：所有已有消息的 actor_type = 'human'
UPDATE messages SET actor_type = 'human' WHERE actor_type IS NULL;
```

type ActorType = 'human' | 'agent' | 'system';

### Task 3：Server Task 状态机强制执行

在 `packages/server/src/routes/tasks.ts` 中：

```ts
function assertValidTransition(from: TaskStatusV2, to: TaskStatusV2): void {
  if (!VALID_TASK_TRANSITIONS[from]?.includes(to)) {
    throw new HTTPException(422, `Invalid transition: ${from} -> ${to}`);
  }
}

function assertValidVersion(task: TaskV2, expectedVersion: number): void {
  if (task.version !== expectedVersion) {
    throw new HTTPException(409, 'Task version conflict');
  }
}
```

- `PATCH /api/tasks/:id/status` 增加状态转换校验 + version 乐观锁
- 状态变更时写入 audit_log
- 依赖检查：如果 task 有 depends_on 未完成，不允许进入 in_progress

**测试**：`packages/server/test/tasksApi.test.ts`

- `backlog -> done` 返回 422
- `ready -> in_progress` 正常
- `in_review -> changes_requested` 正常
- `changes_requested -> done` 返回 422（必须先 qa 或 in_review）
- 并发 patch 相同 version 返回 409
- 状态变更后 audit_log 有记录
